# Semantics as Code Across Enterprise Data Platforms — Authenticated Runtime Test Kit

This artifact supports the paper:

**Semantics as Code Across Enterprise Data Platforms: Empirical Conformance of Vendor-Neutral Metrics on Databricks, Snowflake, and Microsoft Fabric**

The purpose is to test whether one vendor-neutral semantic contract preserves observable business meaning when compiled into and executed through three enterprise semantic runtimes:

1. Databricks Unity Catalog Metric Views
2. Snowflake Semantic Views
3. Microsoft Fabric semantic models (TMDL/DAX)

The artifact is intentionally split into **local preparation** and **authenticated platform execution**. Local tests have been run in the supplied package. Cloud executions require your own accounts, privileges, and credentials; no cloud results are pre-populated.

Use Python 3.10+.

```bash
python -m venv .venv
source .venv/bin/activate       # Windows: .venv\Scripts\activate
pip install -r requirements.txt
./scripts/run_all_local.sh
```

Expected local outcomes:

- Contract schema/policy validation succeeds.
- Business review is reported as `draft` and therefore not production-approved; the local script does not fail unless `--enforce` is supplied.
- Native artifact candidates are generated for all three platforms.
- The independent reference evaluator writes `results/reference.json`.
- Unit tests pass.

## Canonical data fixture

`data/fixture.csv` is the sole source of test data. It deliberately contains:

- integer numerator/denominator columns,
- NULL customer and financial values,
- a zero ordered quantity,
- dates crossing an ISO week-year boundary,
- unequal daily denominators,
- repeated customers/products,
- multiple regions and warehouses.

The cloud platforms should receive this exact file with the explicit types documented in `contracts/semantic_contract.yaml`. Record a SHA-256 of the file in the paper's experiment metadata.

## Independent reference evaluator

The reference evaluator in `saccloud/reference_evaluator.py` uses the Python standard library and `Decimal`; it does **not** use pandas or any vendor engine. It applies the declared contract policies for:

- NULL propagation,
- empty aggregates,
- divide-by-zero,
- exact distinct count,
- ISO-8601 week partitioning,
- non-additive rollup recomputation.

`results/reference.json` is generated by `scripts/04_run_reference.py`.

## Databricks live test

### Required platform features

Use a Unity Catalog-enabled workspace and a SQL warehouse/runtime that supports Metric Views. The generated deployment uses the documented `CREATE OR REPLACE VIEW ... WITH METRICS LANGUAGE YAML AS $$ ... $$` form.

Copy `.env.example` to `.env` and set:

```text
DATABRICKS_SERVER_HOSTNAME
DATABRICKS_HTTP_PATH
DATABRICKS_ACCESS_TOKEN
DATABRICKS_CATALOG
DATABRICKS_SCHEMA
```

The principal needs permission to use the catalog/schema, create a table/view, and use the SQL warehouse.

Run:

```bash
python scripts/05_run_platform.py databricks --deploy
python scripts/11_runtime_query_validation.py databricks
```

This provisions the canonical fixture as a Delta table, deploys a generated Metric View, executes the query suite through that Metric View, and records both native SQL and results.

Verdicts use the contract tolerance:

```text
|x-y| <= max(abs_tol, rel_tol * max(|x|, |y|))
```

Do not replace `NOT_RUN`, `UNSUPPORTED`, deployment failures, or native errors with inferred values. Those are empirical results.

## Recommended paper result categories

Classify each probe as one of:

- `CONFORM` — normalized output matches the independent contract.
- `CONFORM_AFTER_LOWERING` — target cannot express the source form directly, but the adapter applies an explicitly documented semantics-preserving lowering.
- `UNSUPPORTED` — no safe target representation was available.
- `DIVERGENT` — deployed native artifact executes but observable meaning differs.
- `NOT_RUN` — test was not executed; do not treat as evidence.

Classify origins separately:

- target runtime semantics,
- adapter lowering,
- source/contract under-definition,
- governance configuration,
- source-schema drift.

## Important draft limitations

The package was locally validated for contract parsing, compilation, reference calculations, comparison logic, drift/versioning logic, and unit tests. It has **not** been authenticated against your Databricks, Snowflake, or Fabric tenants. Managed-service syntax/features can evolve; record the exact platform versions and keep the raw errors if a generated artifact requires adjustment. Any manual adjustment to a generated artifact must be logged and treated as part of the adapter implementation before reporting conformance.
